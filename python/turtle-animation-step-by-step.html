10. Animation: One Frame At A Time

Continue after Lesson 9, Keyboard-Controlled Turtle. You already know how a key calls a function. Now you will decide when the screen shows a change, then let a timer call a function for you.

Step 1 - Start With One Visible Turtle

Save a new file named animation.py. Type this whole starter program.

CODE
import turtle

screen = turtle.Screen()
screen.setup(600, 800, 0, 0)
t = turtle.Turtle()
t.shape('turtle')
t.penup()
t.speed(5)

t.forward(80)

screen.mainloop()

Run the program. Watch the turtle move. shape('turtle') changes its picture; penup() lets it move without leaving a trail.

Step 2 - Take Charge Of The Redraw

Add this line before you create the turtle.

EDIT VIEW - Gray = already there; dark = add or change
screen.setup(600, 800, 0, 0)
screen.tracer(0)
t = turtle.Turtle()
...

Run the program. The automatic drawing updates are off. The turtle still changes position in the program, but you have not asked the screen to show the result.

Add an update after the movement.

EDIT VIEW - Gray = already there; dark = add or change
t.forward(80)
screen.update()

screen.mainloop()

Run the program. The turtle appears at its new position without showing the journey. screen.update() shows the current picture. It does not move the turtle or repeat your code.

Step 3 - Make One Frame With A Key

Replace the two lines t.forward(80) and screen.update() with this function and setup code. Keep screen.mainloop() last.

EDIT VIEW - Gray = already there; dark = add or change
t.speed(5)

def tick():
    t.forward(5)
    t.left(5)
    screen.update()

screen.listen()
screen.onkey(tick, 'space')
screen.update()

screen.mainloop()

Run the program. Click the turtle window, then press and release the space bar a few times. Each release makes one small move and one turn.

We call one round of work a tick. The picture shown by the update is a frame. Our tick changes the turtle, then shows the frame.

The update inside tick() runs each time you release space. The update at the left edge runs once at startup, so you can see the turtle before pressing anything.

Predict: If you change only t.forward(5) to t.forward(10), what changes? Try it, then change it back to 5.

Step 4 - Let A Timer Call Once

Replace screen.listen() and screen.onkey(tick, 'space') with the timer line below. Leave the function unchanged.

EDIT VIEW - Gray = already there; dark = add or change
    screen.update()

screen.ontimer(tick, 1000)
screen.update()

screen.mainloop()

Run the program. Wait one second. The turtle moves once and stops.

1000 milliseconds is one second. ontimer asks the screen to call tick later, once. Pass tick, without parentheses, just as you did with a keyboard function.

Step 5 - Arrange The Next Tick

Add a timer at the end of the function. It belongs inside the function, at the same indentation as screen.update().

EDIT VIEW - Gray = already there; dark = add or change
def tick():
    t.forward(5)
    t.left(5)
    screen.update()
    screen.ontimer(tick, 100)

screen.ontimer(tick, 1000)
...

Run the program. After the first second, the turtle keeps moving. Each tick arranges one more call for later, then finishes. The screen can handle keys, clicks, and closing the window between ticks.

Replace the startup timer with a call to start immediately.

EDIT VIEW - Gray = already there; dark = add or change
    screen.ontimer(tick, 100)

tick()
screen.update()

screen.mainloop()

Now delete the extra screen.update() between tick() and screen.mainloop(). The first call to tick() already updates the screen.

Run the program. Motion should start right away.

Important: Call tick() once at the bottom. Only the timer inside the function arranges later ticks. Do not connect a key to start another ticking chain.

Step 6 - Compare Two Kinds Of Speed

Change the timer delay inside tick() from 100 to 50. Run it. Then restore 100 and change the forward distance from 5 to 10. Run it again.

A shorter delay requests frames more often. A larger distance moves farther per frame. Change one at a time so you can tell their effects apart. Timing is approximate because drawing takes time too.

With tracer(0), t.speed(5) no longer paces the frames. The timer and the movement per tick do that work.

Finished Lesson - A Small Animation

Compare your program with this version. Use it to find missing or misplaced lines.

CODE
import turtle

screen = turtle.Screen()
screen.setup(600, 800, 0, 0)
screen.tracer(0)
t = turtle.Turtle()
t.shape('turtle')
t.penup()
t.speed(5)

def tick():
    t.forward(5)
    t.left(5)
    screen.update()
    screen.ontimer(tick, 100)

tick()
screen.mainloop()

Try Your Own Changes

Make a wider circular path. Then make the turtle travel around it more slowly. Experiment with distance, turn, and delay separately.

Run the program. Explain which change affected the path and which affected the timing.

Teacher Check

Show the animation. Point to the lines that change the turtle, show the frame, arrange the next tick, and start the first tick.

Explain why screen.update() by itself would not make the turtle move. Explain why the timer receives tick, while the startup line uses tick().

If nothing moves, check that you called tick() at the bottom. If it moves once, look for the timer inside the function. If it changes in the program but not on the screen, check for screen.update().
